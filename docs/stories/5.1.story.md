# Story 5.1: Pet Sitter Profile Creation & Management

**Epic:** 5 — Pet Sitter Profiles & Pay-per-Listing
**Status:** Ready for Review

---

## Story

**As a** pet sitter,
**I want** to create a profile that showcases my services,
**so that** pet owners can find and contact me.

---

## Acceptance Criteria

1. Pet Sitter profile fields: full name, bio (max 500 chars), service area (city/region — up to 3 areas), services offered (multi-select: boarding, dog walking, day care, drop-in visits), rates (free text, max 200 chars, e.g., "€15/night boarding"), experience (years as integer), languages spoken (multi-select), care portfolio (photo upload: max 6 photos, S3 private bucket, CloudFront served).
2. Profile create/update endpoints: `POST /api/v1/sitter/profile` and `PUT /api/v1/sitter/profile`. Auth required, `pet_sitter` role only.
3. Public sitter profile: `GET /api/v1/sitters/{id}` — returns all profile fields above. Contact details (email, phone) are **never** returned. The CTA is a contact form (Story 5.1 AC4).
4. Contact form endpoint: `POST /api/v1/sitters/{id}/contact` — body: `{ name, email, message }`. Sends message to sitter via AWS SES (queued). No contact details in response. Rate-limited: 5 submissions per IP per hour.
5. SitterDashboard shell: profile editor tab + "Contact Submissions" tab listing received messages (name, date, message excerpt).
6. Profile completeness prompt on dashboard if required fields (name, bio, at least one service area, at least one service) are missing.

  ```php
  {
      protected $fillable = [

      ];

              && !empty($this->service_areas)

      }
  }
  ```

  ```typescript
  }

    name: string
    email: string
    message: string
  }

  export const getSitterProfile = (id: number) => axiosClient.get<{ data: SitterProfile }>(`/sitters/${id}`)

  export const getMySitterProfile = () => axiosClient.get<{ data: SitterProfile }>('/sitter/profile')

  export const createSitterProfile = (payload: Partial<SitterProfile>) =>
    axiosClient.post<{ data: SitterProfile }>('/sitter/profile', payload)

  export const updateSitterProfile = (payload: Partial<SitterProfile>) =>
    axiosClient.put<{ data: SitterProfile }>('/sitter/profile', payload)

  export const uploadPortfolioPhoto = (file: File) => {
    const form = new FormData()
    form.append('photo', file)
    return axiosClient.post('/sitter/profile/photos', form, {
      headers: { 'Content-Type': 'multipart/form-data' },
    })
  }

  export const deletePortfolioPhoto = (photoId: number) => axiosClient.delete(`/sitter/profile/photos/${photoId}`)

  export const contactSitter = (sitterId: number, payload: ContactSitterPayload) =>
    axiosClient.post(`/sitters/${sitterId}/contact`, payload)

  export const getContactSubmissions = (page = 1) =>
    axiosClient.get('/sitter/contact-submissions', { params: { page } })
  ```

```php
<?php

namespace Tests\Feature\Sitter;

use Tests\TestCase;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Foundation\Testing\WithFaker;
use Illuminate\Http\UploadedFile;
use Illuminate\Support\Facades\Mail;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\Facades\Storage;
use App\Models\User;
use App\Models\SitterProfile;
use App\Models\SitterPortfolioPhoto;
use App\Mail\SitterContactMail;

class SitterProfileTest extends TestCase
{
    use RefreshDatabase, WithFaker;

    private User $sitter;

    protected function setUp(): void
    {
        parent::setUp();
        $this->sitter = User::factory()->create(['role' => 'pet_sitter']);
        $this->sitter->assignRole('pet_sitter');
    }

    private function validProfilePayload(array $overrides = []): array
    {
        return array_merge([
            'full_name'     => 'Ana Constantin',
            'bio'           => 'I love pets and have 5 years of experience.',
            'service_areas' => ['Chișinău'],
            'services'      => ['boarding', 'dog_walking'],
        ], $overrides);
    }

    public function test_sitter_can_create_profile(): void
    {
        $this->actingAs($this->sitter, 'sanctum')
            ->postJson('/api/v1/sitter/profile', $this->validProfilePayload())
            ->assertStatus(201)
            ->assertJsonStructure(['data' => ['id', 'full_name', 'services', 'is_complete']]);
    }

    public function test_sitter_can_update_profile(): void
    {
        SitterProfile::factory()->create(['user_id' => $this->sitter->id]);

        $this->actingAs($this->sitter, 'sanctum')
            ->putJson('/api/v1/sitter/profile', $this->validProfilePayload(['full_name' => 'Ana Updated']))
            ->assertStatus(200)
            ->assertJsonPath('data.full_name', 'Ana Updated');
    }

    public function test_service_areas_max_3_enforced(): void
    {
        $this->actingAs($this->sitter, 'sanctum')
            ->postJson('/api/v1/sitter/profile', $this->validProfilePayload([
                'service_areas' => ['Chișinău', 'Bălți', 'Cahul', 'Orhei'],
            ]))
            ->assertStatus(422)
            ->assertJsonValidationErrors(['service_areas']);
    }

    public function test_buyer_cannot_create_sitter_profile(): void
    {
        $buyer = User::factory()->create(['role' => 'buyer']);
        $buyer->assignRole('buyer');

        $this->actingAs($buyer, 'sanctum')
            ->postJson('/api/v1/sitter/profile', $this->validProfilePayload())
            ->assertStatus(403);
    }

    public function test_public_sitter_profile_does_not_include_email_or_phone(): void
    {
        $profile = SitterProfile::factory()->create(['user_id' => $this->sitter->id]);

        $body = $this->getJson("/api/v1/sitters/{$profile->id}")
            ->assertStatus(200)
            ->getContent();

        $this->assertStringNotContainsString('email', $body);
        $this->assertStringNotContainsString('phone', $body);
        $this->assertStringNotContainsString('user_id', $body);
    }

    public function test_sitter_can_upload_portfolio_photo(): void

        Storage::fake('s3');

        $file = UploadedFile::fake()->image('portfolio.jpg', 800, 600);

        $this->actingAs($this->sitter, 'sanctum')
            ->postJson('/api/v1/sitter/profile/photos', ['photo' => $file])
            ->assertStatus(201);
    }

        $profile = SitterProfile::factory()->create(['user_id' => $this->sitter->id]);

        $payload = [
```

### §2 — Contact Form Security

The sitter contact form is the only public endpoint in the system that:

1. Accepts user-supplied `email` and sends it elsewhere (to the sitter)
2. Creates a DB record without authentication

Mitigations in place:

- Rate limiting (5/IP/hour) — blocks bulk abuse
- `email:rfc` validation (no `:dns`, see §6) — rejects malformed addresses
- Message min 10 chars — prevents trivial spam
- `sender_ip` stored for abuse reporting, NOT returned to sitter in API (internal audit use only)
- No sitter contact details in response — prevents email harvesting via the contact endpoint

The sitter's email is only used as the mail "To" address internally — it never appears in any API response.

### §3 — Portfolio Photo Storage Pattern

Portfolio photos follow the same S3 private bucket pattern as breeder profile photos (`BreederProfileResource`/`BreederProfileService`), **not** a raw CloudFront URL concatenation as originally specced — see §6:

- S3 key pattern: `sitters/{sitter_profile_id}/portfolio/{uuid}.{ext}`
- URL returned via `S3Service::presignedUrl($s3Key)` (time-limited signed GET URL), computed in `SitterProfileResource`, with a try/catch fallback to `null` on failure
- Magic bytes validation on upload
- `s3_key` never in any API response — only the presigned URL returned

Max 6 photos enforced in `SitterPortfolioService::upload()` before accepting the upload.

### §6 — Implementation Notes / Deviations From Spec

- **Role name:** this codebase's sitter role is `sitter`, not `pet_sitter` (see §1). All middleware, factories, and tests use `sitter`.
- **Service layer added:** `coding-standards.md` requires thin controllers that delegate to services with no business logic in controllers. The original task list (T7–T9) didn't call out services explicitly, but `SitterProfileService`, `SitterPortfolioService`, and `SitterContactService` were added to match every other controller in this codebase (`BreederProfileController` → `BreederProfileService`, etc.).
- **No duplicate `GET /sitter/profile` route:** T7 and T14 both specced a `GET /sitter/profile` endpoint on two different controllers. `SitterProfileController::myProfile()` owns this route (mirroring `BreederProfileController::myProfile()`); `SitterDashboardController` only exposes `contactSubmissions()`.
- **Photo URLs are presigned S3 URLs, not CloudFront:** this codebase has no CloudFront URL helper anywhere (`BreederDocument`, `BreederProfile` photos all resolve via `S3Service::presignedUrl()`). Portfolio photos follow the same pattern for consistency — see §3.
- **Contact email validation:** `email:rfc,dns` was dropped to `email:rfc` (no DNS rule). A DNS-lookup validator makes the request network-dependent and is flaky in CI/offline environments; no other `email` rule in this codebase uses `:dns`.
- **`/sitters/{id}` uses the sitter's `user_id`**, not `sitter_profile.id` — this matches the established `GET /breeders/{id}` convention (`BreederProfileController::show(int $id)` looks up by `user_id`) so the two public profile endpoints behave identically.
